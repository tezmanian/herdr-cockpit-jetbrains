How to read the Herdr sidebar

The sidebar is a live view of your Herdr server: every space, the agents and shells in it, and what each one is doing. Nothing runs inside the IDE. Agents and shells keep running in Herdr, and the editor tabs Herdr Cockpit opens are live views of Herdr's panes.

Getting started

  1. Make sure Herdr runs. If it doesn't, the sidebar offers Start Herdr (see When Herdr isn't running).
  2. Click a space. Its folder is added to the project as a content root and every agent and shell opens as an editor tab.
  3. Drop files on a pane's tab (from the project view, an editor tab or Finder): their paths are typed in at the prompt (as @path for Claude Code, which attaches the file), so you can ask the agent about them.
  4. Optional: the Herdr plugin jumps here from Herdr in your terminal, and Show plan limits… in Usage adds Claude Code's limits.

Create, rename and close

New space (next to "Spaces")
Pick one of the window's projects (the project and the ones attached to it; several spaces per project are fine), Choose a folder…, or New git worktree of an existing space: a separate checkout on a new branch, so an agent can work without touching your current branch (Herdr puts it in ~/.herdr/worktrees/<repo>/<branch>). Then name it and choose what to start. The new pane opens as an editor tab right away.
New tab (bottom of a space card, or right-click a space)
Choose Shell, Shell with a name… or an agent. The agents listed first come from the Agents setting; More agents… lists every agent Herdr can start. The tab opens right away; an agent starts in it in the background (a notification shows progress).
Rename… (right-click)
Spaces take any name. Shells too (empty = use the tab name). Agent names are identifiers in Herdr: lowercase letters, digits, - and _ (for example reviewer). The open editor tab is renamed as well.
Close in Herdr… (right-click)
Stops the shell or agent, or a whole space, after asking. (Closing an editor tab can do this too: see Pane tabs.) For a worktree space you can also delete its worktree folder; Herdr refuses if it has uncommitted changes and asks before forcing it.

Herdr can report an agent as started even when that agent isn't installed. If a new agent tab shows "command not found", install the agent's CLI first.

Pane tabs

  • Click any agent or shell row to open it in an editor tab with the same name as the row. Clicking again brings the existing tab forward.
  • The tab is a terminal drawn from Herdr's live stream of the pane (herdr terminal session control --takeover): there is no shell inside it, so every key goes straight to the agent or shell in Herdr.
  • Selecting and copying work like in the IDE's terminal. The mouse wheel scrolls the pane's scrollback in Herdr.
  • Closing a tab only detaches: the program keeps running in Herdr. With the setting Closing a pane's tab yourself set to ask or always, closing a tab with its X closes the pane in Herdr too (ask: idle shells right away, agents and busy shells after asking). Tabs the plugin closes, and closing the project or the IDE, never close anything in Herdr.
  • A pane renamed in Herdr renames its tab here within a few seconds. A pane closed in Herdr closes its tab.
  • If the stream ends (Herdr stopped, another client took the pane over), the tab keeps its last screen with a note. Close it, or click the row to open it again.
  • Open Herdr TUI (Tools | Herdr, the status bar menu, the disconnected screens) runs Herdr's own full-screen interface in an editor tab, against the same session. Closing that tab ends only that client.

  • Status bar (bottom right): ⬢ 1 blocked · 2 done while agents need you, else ⬢ Herdr; ⬢ Herdr: disconnected when Herdr isn't connected. Hover for the Herdr version and socket. Click it to jump to the agent that needs you (blocked first); with nothing waiting, it opens a menu with Refresh, Start Herdr, Stop Herdr (asks first: every agent and shell stops), Settings and Copy Diagnostics. Follow mode

When you switch spaces in Herdr itself (for example in your terminal), the IDE switches too (setting Follow Herdr's focus). To avoid hijacking unrelated projects it only acts in projects where you've already switched a space from the sidebar.

The Herdr plugin: from Herdr's terminal to here

The companion Herdr plugin (herdr-plugin/ in this plugin's repository) works from Herdr's side. Install it with herdr plugin install tezmanian/herdr-cockpit/herdr-plugin, then bind its actions to keys in Herdr's config.toml, or run them from a terminal with herdr plugin action invoke tezmanian.herdr-cockpit-jetbrains.open (or .open-file, .review):

Open in JetBrains IDE
Brings the IDE to the front and switches to the space you're in, with the focused pane's tab in front.
Open selected file in JetBrains IDE
Select a location in any pane (src/app.php:42:7, app.ts(42,7), app.ts#L42, a Python traceback line) and it opens here at that line.
Review changes in JetBrains IDE
The focused space's changes as diffs.

The IDE tells the plugin where to find it in ~/.herdr-cockpit/jetbrains.json (its built-in server's port and a random token, readable only by you). Links only select a space, a pane or an existing file; a link for another Herdr session is refused. With two JetBrains IDEs open, links go to the one started last.

When Herdr isn't running

Your spaces and agents live in the Herdr server, so without it the sidebar has nothing to show. It says why and offers the next step:

The sidebar saysWhat to do
Herdr isn't runningStart Herdr starts the server in the background, with no window and with a terminal-like environment (the IDE's own variables aren't passed on to your panes). It keeps running after you quit the IDE, so your agents keep running too; stop it with Stop Herdr in the status bar menu or herdr server stop. Open Herdr TUI runs Herdr's full interface in an editor tab instead.
Herdr stopped unexpectedlyIt crashed and left its socket file behind. Start Herdr is safe: Herdr restores your spaces, tabs and folders. Agents with a Herdr integration (such as Claude Code) resume their sessions; others come back as shells.
Herdr isn't installedInstall Herdr opens herdr.dev. If it is installed somewhere unusual, set herdr binary.
This Herdr version isn't compatibleHerdr and Herdr Cockpit speak different protocol versions: update Herdr (herdr update) or Herdr Cockpit.
Herdr isn't answeringThe server runs but doesn't respond: Retry, or Copy diagnostics for a bug report.
Short interruptions
If the connection drops briefly (for example while Herdr updates), the sidebar keeps the last view, greyed out, with Reconnecting to Herdr…. It reconnects by itself every few seconds (backing off to 10 s).
If Herdr stops while you work
You get one notification (your agents stopped with it) and the status bar shows ⬢ Herdr: disconnected. Open pane tabs keep their last screen with a note that the stream ended.
Copy diagnostics
Copies the connection state, the herdr path and socket path the plugin uses, and its recent log, for a bug report. It includes local file paths, so check it before sharing.

Privacy and safety

  • Everything shown comes from your Herdr server and from files on this machine. Shell output, agent screens and usage numbers never leave your computer. The only network request is Codex's own usage check, which Codex makes with its own login.
  • Herdr Cockpit never reads the agents' logins or tokens. Claude's plan limits come only from the status line you opt into.
  • The git line and Review run only in trusted projects. On top of that, every git call switches off the commands a repository can define for itself that are known to run during a status check (fsmonitor, file filters, hooks).
  • Links from the Herdr plugin need the random token in ~/.herdr-cockpit/jetbrains.json; requests from web pages are refused.

Troubleshooting

The sidebar says Herdr isn't running, installed or answering
See When Herdr isn't running. If you use a named Herdr session or a custom socket, set Socket.
A pane tab won't open
An IDE started from the Dock or an app launcher may not find herdr on PATH. Set herdr binary.
Keys like Ctrl+B don't reach Herdr
The IDE's keymap may take them first. Remove the conflicting shortcut in Settings | Keymap.
Agents show up as shells running "zsh (kiro-cli-term)"
Kiro's shell integration wrapped Herdr's pane shells, which hides agents from Herdr. Stop Herdr (herdr server stop) and click Start Herdr again: panes then start without the wrapper.
No git line under a space
The folder isn't a git repository, or the project isn't trusted.
An agent is missing from Usage
Usage lists only Claude Code, Codex and Kiro, and only while one of their panes is open in Herdr.
Claude Code shows no bars
Click Show plan limits…. Bars need a claude.ai Pro or Max plan and appear after Claude's next reply.
Codex shows "as of …" instead of "live"
The live check couldn't reach Codex (not installed where the IDE looks, or logged out); the numbers come from its logs instead.
Something looks wrong
Right-click it → Show Raw, or Copy Diagnostics from the status bar menu. Help | Show Log has the plugin's log lines.
